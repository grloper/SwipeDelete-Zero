# Connect Google backup on SwipeRise

The Play test build can upload selected photos and videos to Google Photos and back up kept or staged files to an app-created Google Drive folder. Drive originals uploaded with the current manifest can be discovered after a clean install and restored to a file you choose. The app compares a fresh download and restored bytes against the SHA-256 hash of the original. **Local cleanup remains locked** while the complete backup-to-deletion path is validated.

To connect, open **Settings → Connect Google account**. The in-app setup help displays the package name and SHA-1 of the APK actually installed on your device. Google sign-in requires an Android OAuth client in a Google Cloud project with that exact package and SHA-1, the Drive and Photos APIs enabled, an OAuth consent screen, and your account as a test user while the app is in Testing mode. Debug APKs use `com.swipedelete.zero.debug`; Play release builds use `com.swipedelete.zero` and a different certificate. A debug fingerprint copied into a release OAuth client will fail.

After connecting, choose **Back up now** in the cloud screen for Drive, or swipe a review card up to archive an eligible image or video to Photos. The Drive scope grants access to files created by this app, not your full Drive. Photos scopes allow uploading and reading app-created items, not browsing your entire Photos library. You can check the connection in the setup help. Use **Restore** to inspect eligible Drive originals and save one to a destination chosen with Android's document picker. Files created before the current restore manifest might not appear after clearing app data.

If sign-in reports developer error `code 10`, verify the package and signing fingerprint displayed by the installed app against the Android OAuth client. If the account is denied, check consent-screen test users and required APIs. A live Google account and configured OAuth project are necessary to validate backup and restore end to end; automated CI cannot perform this sign-in.

The F-Droid edition is offline and has no Google backup. This Android app currently has no iCloud integration: an Apple CloudKit container would require separate Apple developer configuration and would only hold this app's own data, not browse or verify arbitrary iCloud Photos or iCloud Drive files.
